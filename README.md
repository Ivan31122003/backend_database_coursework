# Система управления сотрудниками и проектами — backend

Серверная часть учебного проекта по дисциплине «Системы управления базами данных». Приложение предоставляет REST API для управления сотрудниками, отделами, проектами и связями между ними. Оно работает с PostgreSQL, поддерживает авторизацию пользователей и проверяет права доступа к маршрутам на уровне базы данных.

Клиентская часть проекта: [frontend_database_coursework](https://github.com/Ivan31122003/frontend_database_coursework).

## Возможности

- авторизация по имени пользователя и паролю с выдачей JWT;
- CRUD-операции над сотрудниками, отделами и проектами;
- управление связью «сотрудник — отдел»;
- получение данных «сотрудники — проекты» для экспорта на клиенте;
- разграничение доступа к маршрутам по ролям пользователя;
- выполнение SQL-запросов к PostgreSQL через пул подключений;
- обработка ошибок и ограничений, возвращаемых триггерами базы данных.

## Быстрый запуск

### Требования

- Node.js и npm;
- PostgreSQL;
- база данных со схемами, таблицами, функциями и триггерами, используемыми приложением.

API рассчитан на базу данных `database_coursework`. В ней используются, в частности:

- таблицы `public.employees`, `public.departments`, `public.projects`, `public.departments_employees`;
- таблица `admin.users`;
- функция `admin.check_route_access(user_id, route)` для проверки прав;
- функция `get_employees_projects()` для данных экспортируемой таблицы.

### Установка и запуск

```bash
git clone https://github.com/Ivan31122003/backend_database_coursework.git
cd backend_database_coursework
npm install
npm start
```

По умолчанию сервер доступен по адресу `http://localhost:3000`. Чтобы изменить порт, передайте переменную окружения `PORT` при запуске.

### Настройка подключения к БД

Параметры подключения находятся в [`db.js`](db.js): хост, порт, имя базы данных, пользователь и пароль PostgreSQL. Перед запуском укажите значения, соответствующие вашей локальной базе данных.

> **Важно:** перед публикацией репозитория не храните реальные пароли в `db.js`. Для публичного проекта следует перенести их в переменные окружения и добавить файл с локальными значениями в `.gitignore`.

## API

Все маршруты, кроме авторизации, доступны по префиксу `/api` и принимают `POST`-запросы. Защищённые маршруты ожидают JWT в поле `token` тела запроса; возможность выполнения операции дополнительно проверяется функцией `admin.check_route_access` в PostgreSQL.

| Маршрут | Назначение |
| --- | --- |
| `POST /api/auth` | Авторизация пользователя и получение JWT |
| `POST /api/employees/{get, put, update, delete}` | Получение и изменение данных о сотрудниках |
| `POST /api/departments/{get, put, update, delete}` | Получение и изменение данных об отделах |
| `POST /api/projects/{get, put, update, delete}` | Получение и изменение данных о проектах |
| `POST /api/departments_employees/{get, put, update, delete}` | Управление связями сотрудников и отделов |
| `POST /api/employees_projects/get` | Получение данных о сотрудниках и проектах для экспорта |
| `POST /api/users/get` | Получение списка пользователей для раздела администрирования |

### Пример авторизации

```http
POST /api/auth
Content-Type: application/json

{
  "username": "user",
  "password": "password"
}
```

При успешной проверке сервер возвращает:

```json
{
  "success": true,
  "token": "<JWT>"
}
```
